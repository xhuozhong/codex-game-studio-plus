# 4.0 升级说明

保留原有 15 个 Skill，新增 6 个，共 1 个总导演 + 20 个专家。新版默认继续服务现有浏览器游戏；不因增加专家而迁移项目引擎，也不自动启动二十个代理。

## 安装与兼容

解压后运行 REPAIR_WINDOWS.cmd：所有同名旧目录（包括用户本地修改）先整体备份，再安装清单中的 21 个 Skill。默认普通安装遇到冲突会先停止。备份与卸载规则沿用原有安装器，位置见主 README。不要同时保留重复的用户级/项目级 Skill 并误判加载版本。

新检查工具使用 Python 3.10+ 标准库。精灵归一化继续需要 Pillow。实际 GLB 转换需要已有 Node 与 glTF Transform CLI；已在本次测试工作目录验证 4.4.2，不将整套 Node 依赖塞进离线包或修改用户全局工具链。

## 状态与失败处理

素材记录区分 draft、processed、verified。`--release` 只检查声明、哈希和证据文件存在；还要人工/代理核实许可内容、看检/听检和真实项目覆盖率。不得用批量改状态、自动重写哈希来消除检查失败。

地图工具不解释所有格式；音频工具不测 LUFS 或代替听检；本地化工具不解析 ICU 或证明翻译正确；GLB 格式检查不证明渲染、动画、解码和性能正确。完整边界与实测范围见 [验证记录](validation.md)。

## 推荐落地顺序

先选一个可玩的场景，明确素材清单和风格 → 复用已有资产/按需生成 → 结构和许可预检 → 真实导入与事件绑定 → 试玩、看检、听检、存档与回归 → 扩充内容。生产规范由项目决定，不套用样例的地图、数量或固定面数预算。
