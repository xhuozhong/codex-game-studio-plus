# 从 1 + 10 升级到 1 + 14

Plus 是单独仓库，未改变旧仓库。默认入口仍为 `$game-studio-director`，新增专家不会每次全部加载。

## 推荐试用路径

1. 保留旧包与本地改动。
2. 下载并完整解压 Plus；先运行 `scripts/validate.ps1`。
3. 使用 `-Scope Project -ProjectRoot` 安装到一个现有测试项目，不改用户级安装。
4. 在 Codex 中确认加载来源，试一个项目内的小改动并实际运行。
5. 确认要全局切换时，运行 `REPAIR_WINDOWS.cmd`，把同名旧目录备份后替换。

两个版本含同名 Skill，因此“两个仓库独立”不等于“同一安装目录可同时装两个同名版本”。旧 `.codex/skills` 下的 Skill 不会被这个安装器自动整理。

## 回退

Plus 卸载只把属于本包的目录移到备份。恢复旧版前，先确认对应作用域无同名目录，再把升级时备份的旧 Skill 文件夹复制回原 `skills/` 目录。不要把整个备份目录放进 `skills/`，也不要覆盖尚未保存的新修改。

安装器没有修改 Codex 配置、账号或外部服务，也没有安装 Phaser/Blender/Pillow。若失败信息提到路径链接或权限，先检查目标位置，不要通过提权盲目绕过。

## 暂不默认纳入

- Unity MCP：编辑器与连接服务是独立依赖，需匹配 Unity 项目、版本和授权。
- Godot Agent：需核对 Python/操作系统与编辑器支持范围；不承诺 Windows 实时编辑器控制。
- 其他着色器/游戏设计集合：需逐项核实 API、许可和可执行资源后再选入。

这些是后续评估方向，不是本版已安装或已验证功能。
